# @az/chat-render — the chat renderer

What draws an az chat answer on a page: prose through the markdown subset,
charts, tables, stats, image cards, dashboards, explores and maps, the
working signs (dots, caret, a held component's placeholder) and the answer's
bar — each component a filled copy of a template the chat word made, every
model string written as text, no attribute or address chosen by the model,
links only from the allow-list.

It is the code an `az build` site's chat panel runs (copied into the site's
`src/az/chat-render/`; the panel in `@az/overlay` imports it as
`#chat-render/…`). An app has no build and no pre-rendered page, so the
package also carries, per theme, the chat word's own shell as data
(`themes/<name>.ts`, generated by `scripts/gen-chat-themes.mjs` from the
same emitters and stylesheet compiler a site's build runs) and its
stylesheet (`themes/<name>.css`), and builds the templates at runtime —
element by element, never by parsing markup
([chat-block-spec §22.3](../../docs/chat-block-spec.md)).

Not published to a registry (the package is `private`); a workspace package
depends on it with `"@az/chat-render": "workspace:*"`. For React, use
`@az/chat-react`'s `<AzAnswer>`, a thin wrapper over this.

## Example

[`examples/answer.ts`](examples/answer.ts) — a browser module; run
`node scripts/chat-lib-e2e.mjs --serve` and open
`http://127.0.0.1:4800/example/chat-render/answer`:

```ts
// Run: node scripts/chat-lib-e2e.mjs --serve, then open http://127.0.0.1:4800/example/chat-render/answer
import { mountAnswer } from '@az/chat-render/chat-answer-mount.ts';
import * as midnight from '@az/chat-render/themes/midnight.ts';

// The checker's events for one answer, as the chat runtime or the chat API hands them over.
const events = [
  { type: 'text', s: 'Here are **this week\'s** orders.\n\n' },
  { type: 'hold', word: 'chart' },
  { type: 'block', block: { chart: { kind: 'bar', title: 'Orders by status', unit: null, src: 'model', series: [{ name: 'Orders by status', points: [['paid', 12], ['open', 3]] }] } } },
  { type: 'block', block: { cta: { label: 'Talk to us', to: '/contact' } } },
  { type: 'block', block: { ask: 'How do refunds work?' } },
  { type: 'done' },
] as const;

// The page loads the theme's stylesheet itself (themes/midnight.css): no inline style, so a strict policy holds.
const answer = mountAnswer(document.getElementById('app')!, {
  theme: midnight,
  components: ['chart', 'cta'],
  destinations: ['/contact'],
  onAsk: (q) => { document.title = `Asked: ${q}`; },
  onAnnounce: (said) => { document.getElementById('status')!.textContent = said; },
});
for (const e of events) answer.push(e);
document.documentElement.dataset.azExample = 'drawn';
```

The page loads `themes/midnight.css` with a `<link>`; nothing inline, so a
policy of `script-src 'self'; style-src 'self'` holds.

## API

| Import | What |
|---|---|
| `@az/chat-render/chat-answer-mount.ts` | `mountAnswer(container, { theme, components, destinations, images, scheme, backend, tiles, onAsk, onAnnounce, onCopy })` → `{ push(event), reset(), destroy(), root, answer, ended }` — the framework-free core |
| `@az/chat-render/themes/<name>.ts`, `themes/<name>.css` | the six themes (midnight, paper, signal, clay, petal, volt): the shell, and its stylesheet scoped to `[data-az-chat-root][data-az-theme="<name>"]` |
| `@az/chat-render/chat-templates.ts` | `chatShell(doc, theme, scheme)`, `buildTemplate`, `hostImages` — the shell as DOM |
| `@az/chat-render/chat-answer-view.ts` | `liveAnswer`, `answerDrawer`, `drawBlock` — the drawing the site's panel and `mountAnswer` share |
| `@az/chat-render/chat-logic.ts`, `chat-history.ts`, … | the page runtime's pure rules: event shapes, copy, follow, the kept conversation |

`push` takes the answer checker's events (`text`, `hold`, `block`, `done`,
or `error`) and checks each again — the page is the second check, as on an
az site. `images` maps a card's image key to the app's own `{ src, alt }`
(https or the app's own path); nothing else writes an image address but a
row image at the backend's own path. A map's library (and its worker) loads
only when an answer holds a map; without WebGL a map is its list.

**Theming.** Every colour is a `var(--az-color-…)` the theme's stylesheet
declares on the renderer's root, light and dark (`prefers-color-scheme`,
or `scheme` / `data-scheme` to pin one). A host maps its own tokens by
declaring those properties on the root, e.g.
`[data-az-chat-root] { --az-color-accent: var(--app-primary); }`.

**Limits.** An FAQ's items show open: their disclosure behaviour is the site
runtime's (`@az/overlay`), not this package's. Share links and the panel's
float are the site's (server features and page layout).

## Tests

`node --experimental-strip-types --test packages/chat-render/test/*.test.ts`
(part of `pnpm verify`); the themes are held to their generator by
`scripts/lib/chat-themes.test.mjs`; `pnpm test:chat-lib` draws answers in
Chromium, Firefox and WebKit, through this core and through `<AzAnswer>`;
`pnpm test:chat` runs every az site chat check through the same files.
